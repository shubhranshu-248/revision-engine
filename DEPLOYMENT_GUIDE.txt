================================================================================
0.  DO I NEED A DATABASE?
================================================================================

Short answer:  NO. You do NOT need a database platform for Revio.

Why not?

  Revio serves STATIC files. When a student clicks "Download", the browser
  just fetches a .pptx or .docx file directly from your hosting provider
  (Vercel/GitHub Pages). There's no login, no user account, no per-user data,
  no search index, no comments, no ratings, no analytics beyond what
  Vercel/GitHub gives you for free.

  Everything the site needs to know — which subjects exist, which chapters
  are live, what files each chapter has — lives inside ONE JSON file:

      site/src/data/content.json

  That JSON file IS your "database". It's a text file that you edit yourself,
  commit to Git, and push. When you push, Vercel/GitHub rebuilds the site
  and the new content is live.

Advantages of the current setup (no database):

  - $0/month hosting (both Vercel Hobby and GitHub Pages are free forever
    for personal use at your scale).
  - Instant loads. There's no server to wake up, no query to run. The site
    is just files on a CDN.
  - Zero maintenance. Nothing to patch, nothing that can "go down".
  - You can host up to ~500 files easily on GitHub (100 MB per file limit,
    5 GB soft repo limit) and effectively unlimited on Vercel.
  - Recruiters looking at your GitHub see a clean, coherent React project.

When you WOULD outgrow this (i.e. actually need a database):

  - You start collecting student sign-ups, saved progress, or paid access.
  - You want a search bar that ranks 10,000+ documents.
  - Multiple people (not just you) need to upload files via a web form
    rather than by pushing to Git.
  - You want to track per-file download counts for every user.

  None of these apply to Class 10 CBSE revision packs. Stay static. If any
  of those become true in the future, section 10 has the migration path.

1.  WHAT REVIO ACTUALLY IS  (MENTAL MODEL)
================================================================================

Think of Revio as a very fancy, styled file browser that always shows the
five subjects in the same order and never gets messy.

  YOUR COMPUTER                         THE INTERNET
  -------------                         ------------
  Revio                       Vercel / GitHub Pages
  generates .pptx & .docx        →      hosts the whole site as
  files inside the Revision                static files. Downloads go
  Engine's output folder                   directly from their CDN.
                                                    ↑
                                                    │
  You copy those files to:                          │
  site/public/assets/<subject>/                     │
  and edit content.json.                     Every time you  git push,
                                             Vercel/GitHub  rebuilds
  git add → git commit → git push  ─────────→  the site automatically.

There are exactly 4 moving parts:

  1. The React frontend        (site/src/)
  2. The content index         (site/src/data/content.json)
  3. The actual downloads      (site/public/assets/<subject>/*.pptx|docx)
  4. The Git repo on GitHub    (the "source of truth")

That's it. Everything else in section 2–10 below is just how to wire those
four things together.

2.  ONE-TIME SETUP — TOOLS YOU NEED ON YOUR WINDOWS PC
================================================================================

Do these once, ever. You won't touch them again after this.

  a) Node.js (LTS version)
     - Go to  https://nodejs.org
     - Download the "LTS" .msi installer for Windows.
     - Run it, click Next until it finishes. Default options are fine.
     - Verify: open PowerShell (Win + R → "powershell" → Enter) and run:
           node --version
           npm --version
       Both should print a version number.

  b) Git
     - Go to  https://git-scm.com/download/win
     - Install with default options. On the "adjusting your PATH" screen
       pick the middle option ("Git from command line and 3rd-party
       software").
     - Verify:
           git --version

  c) A GitHub account
     - Sign up at  https://github.com  (use the same email you'd like
       recruiters/students to see).
     - Suggested username: something professional like your real name.
       Example: github.com/shubhranshu-sahu

  d) A code editor (recommended, not required)
     - VS Code from  https://code.visualstudio.com
     - Opens content.json comfortably and shows syntax errors as you type.

You're set. You never install any of the above again.

3.  PUSH THE PROJECT TO GITHUB — THE SOURCE OF TRUTH
================================================================================

GitHub is where the project's canonical copy lives. Vercel and GitHub Pages
both read from GitHub to build and deploy.

  Step 1 — Create the empty repo on GitHub
  ----------------------------------------
    1. Go to  https://github.com/new
    2. Repository name:    revio
    3. Description:        Revio — A static resource hub for CBSE Class 10
                           revision materials across Physics, Chemistry,
                           Mathematics, Biology, and Social Science.
    4. Public. (Recruiters can't see private repos.)
    5. Do NOT tick "Add a README" or "Add .gitignore" — the project already
       ships with those.
    6. Click "Create repository".
    7. On the next page, copy the URL that looks like:
           https://github.com/<your-username>/revio.git

  Step 2 — Push the local project
  --------------------------------
    Open PowerShell IN the project's root folder. The easiest way:
      - In File Explorer, navigate to  E:\Claude Projects\Revio
      - Shift + Right-click inside the folder → "Open PowerShell window here"

    Then run, one line at a time:

        git init
        git add .
        git commit -m "chore: initial Revio site"
        git branch -M main
        git remote add origin https://github.com/<your-username>/revio.git
        git push -u origin main

    First push may ask you to log into GitHub in a browser popup. Approve it.

    Refresh your GitHub repo page — you should now see all the files.

  Step 3 — Verify locally that everything works
  ----------------------------------------------
    Still in PowerShell:

        cd site
        npm install
        npm run dev

    Open  http://localhost:5173  in your browser. You should see Revio.
    Press Ctrl + C in the PowerShell window to stop the dev server.

You are now in "development" mode. Next, we make it live.

4.  DEPLOY OPTION A — VERCEL   (RECOMMENDED)
================================================================================

Vercel is the fastest way to get Revio online. It's free for personal
projects, gives you a fast global CDN, and auto-deploys every time you push
to GitHub.

  Step 1 — Sign up
  -----------------
    1. Go to  https://vercel.com/signup
    2. Click "Continue with GitHub" and authorize Vercel.
    3. Pick the free "Hobby" plan. No credit card needed.

  Step 2 — Import the repo
  -------------------------
    1. Vercel dashboard → "Add New..." → "Project"
    2. Under "Import Git Repository" you should see "revio". Click Import.
    3. IMPORTANT — Vercel will ask a few questions:

         Project Name:            revio   (or anything, this becomes
                                             part of the default URL)
         Framework Preset:        Vite       (should auto-detect)
         Root Directory:          site       ← **CLICK EDIT AND SET THIS**
                                              (because your React project
                                              lives in the "site" subfolder,
                                              not the repo root)
         Build Command:           npm run build   (auto)
         Output Directory:        dist            (auto)
         Install Command:         npm install     (auto)

    4. Click "Deploy".

    Wait about 60 seconds. You'll see a confetti animation and a live URL
    that looks like:

         https://revio.vercel.app
         (or https://revio-<your-username>.vercel.app)

    That link works from anywhere in the world. Share it with students.

  Step 3 — From now on, deployment is automatic
  ----------------------------------------------
    Every time you push to GitHub's main branch, Vercel:
      1. Detects the push.
      2. Runs  npm install  and  npm run build  in the "site" folder.
      3. Publishes the new version to the same URL.
      4. Sends you an email if the build fails.

    Typical turnaround: 40–90 seconds from `git push` to the site being live.

  Step 4 — (Nice to have) Vercel Analytics
  -----------------------------------------
    Free traffic dashboard: dashboard → your project → "Analytics" tab →
    Enable. No code changes needed.

5.  DEPLOY OPTION B — GITHUB PAGES   (100% FREE, GITHUB-ONLY)
================================================================================

Use this if you'd rather stay entirely inside GitHub. The project already
ships with the necessary workflow file at:

    site/.github/workflows/deploy.yml

  Step 1 — Move the workflow file to the repo root
  -------------------------------------------------
  GitHub Actions expects workflow files at  .github/workflows/  under the
  REPOSITORY ROOT, not inside subfolders. Move the folder:

      In PowerShell at E:\Claude Projects\Revio :

          Move-Item site\.github .

  Step 2 — Fix the Vite base path
  --------------------------------
  GitHub Pages serves your site at
      https://<username>.github.io/revio/
  (note the trailing "/revio/"). Open  site/vite.config.js  and change:

          base: '/',
  to:
          base: '/revio/',

  Save.

  Step 3 — Commit and push
  -------------------------
      git add .
      git commit -m "ci: enable GitHub Pages deploy"
      git push

  Step 4 — Enable GitHub Pages
  -----------------------------
    1. On GitHub, open your repo → Settings → Pages.
    2. Under "Build and deployment", set Source to "GitHub Actions".
    3. Go to the "Actions" tab. Wait for the "Deploy to GitHub Pages"
       workflow to finish (green tick, ~1–2 minutes on first run).
    4. Your live URL:
             https://<your-username>.github.io/revio/

  From now on, every push to main triggers the same workflow automatically.

6.  CUSTOM DOMAIN (OPTIONAL) — E.G. revio.in
================================================================================

  Buy a domain from any registrar — GoDaddy, Namecheap, Google Domains, or
  Hostinger. A .in domain typically costs Rs. 800–1,200 per year.

  ON VERCEL:
    1. Project → Settings → Domains → "Add Domain".
    2. Type revio.in (or www.revio.in).
    3. Vercel gives you either an A record or CNAME to add in your domain
       registrar's DNS panel. Copy-paste those exact values.
    4. Save. HTTPS is auto-provisioned. Usually live within 5–30 minutes.

  ON GITHUB PAGES:
    1. Repo → Settings → Pages → "Custom domain" → type revio.in.
    2. In your registrar's DNS panel, add:
             A     185.199.108.153
             A     185.199.109.153
             A     185.199.110.153
             A     185.199.111.153
       (These are GitHub's official IPs; if in doubt, GitHub's Pages docs
       show them at pages.github.com's "custom domain" article.)
    3. GitHub → repo Settings → Pages → tick "Enforce HTTPS" once it lets you.

7.  THE 3-STEP CONTENT UPLOAD WORKFLOW
   (Do this every time you finish a new chapter in the Revio)
================================================================================

This is the workflow you'll use dozens of times over the year. It's
deliberately kept to 3 steps.

  You have just generated (say):
     10 - Light Reflection and Refraction (Quick Revision Slides).pptx
     10 - Light Reflection and Refraction (Mindmap).pptx
     10 - Light Reflection and Refraction (Cheatsheet).docx
     10 - Light Reflection and Refraction (Worksheet).docx
     10 - Light Reflection and Refraction (Solutions Key).docx

  Chapter 10 Physics belongs to the "physics" subject folder.

  STEP 1 — Drop the files in the right folder
  --------------------------------------------
    Copy all 5 files into:

         E:\Claude Projects\Revio\site\public\assets\physics\

    Rules:
      - Folder name = subject slug (physics, chemistry, mathematics,
        biology, social-science). Case-sensitive on Linux hosts.
      - Filename MUST match the Revio convention:
           {ChapterNo} - {Chapter Name} ({Doc Type}).{ext}
        Because whatever filename you put here is EXACTLY what the site's
        download link will point to.
      - Keep spaces and hyphens as-is. The site handles URL-encoding.

  STEP 2 — Update content.json
  -----------------------------
    Open  E:\Claude Projects\Revio\site\src\data\content.json  in VS Code
    (or Notepad — but VS Code will flag JSON syntax errors, safer).

    Find the "physics" subject → find the chapter with slug
    "light-reflection-and-refraction". It currently looks like:

        {
          "id": "ph-ch10-light",
          "number": 10,
          "name": "Light — Reflection and Refraction",
          "slug": "light-reflection-and-refraction",
          "status": "coming-soon",
          "files": []
        }

    Change it to:

        {
          "id": "ph-ch10-light",
          "number": 10,
          "name": "Light — Reflection and Refraction",
          "slug": "light-reflection-and-refraction",
          "status": "available",
          "files": [
            {
              "type": "Quick Revision Slides",
              "format": "pptx",
              "filename": "10 - Light Reflection and Refraction (Quick Revision Slides).pptx",
              "size": "4.2 MB"
            },
            {
              "type": "Mindmap",
              "format": "pptx",
              "filename": "10 - Light Reflection and Refraction (Mindmap).pptx",
              "size": "1.8 MB"
            },
            {
              "type": "Cheatsheet",
              "format": "docx",
              "filename": "10 - Light Reflection and Refraction (Cheatsheet).docx",
              "size": "280 KB"
            },
            {
              "type": "Worksheet",
              "format": "docx",
              "filename": "10 - Light Reflection and Refraction (Worksheet).docx",
              "size": "320 KB"
            },
            {
              "type": "Solutions Key",
              "format": "docx",
              "filename": "10 - Light Reflection and Refraction (Solutions Key).docx",
              "size": "410 KB"
            }
          ]
        }

    Notes:
      - Two edits only: status  →  "available"    and    files  →  [...]
      - Values allowed for  "type":
            "Quick Revision Slides"
            "Mindmap"
            "Cheatsheet"
            "Worksheet"
            "Solutions Key"
      - Values allowed for  "format":  "pptx"  or  "docx"
      - "size" is whatever Windows Explorer shows for that file
        (right-click file → Properties → "Size", pick MB or KB).
      - Commas matter in JSON. Every item in the "files" array is separated
        by a comma EXCEPT the last one. VS Code highlights errors in red.
      - You do NOT need to list all 5 file types — if you've only made
        the slides so far, just list slides, ship it, add the others later.

  STEP 3 — Commit and push
  -------------------------
    In PowerShell, at the repo root  E:\Claude Projects\Revio :

        git add .
        git commit -m "content(physics): add Chapter 10 — Light"
        git push

    That's it. Within 1–2 minutes:
      - Vercel/GitHub rebuilds the site.
      - The chapter card on the site turns from muted (coming soon) to
        clickable, showing 5 file chips.
      - Clicking it opens the chapter detail page with 5 download cards.
      - Clicking Download starts the .pptx/.docx download from the CDN.

  Optional shortcut: test locally first
  --------------------------------------
    If you want to eyeball changes BEFORE pushing:

        cd site
        npm run dev

    Visit http://localhost:5173 — your changes are live locally. Ctrl+C
    to stop. Push only when you're happy.

8.  HOW THE FOLDER STRUCTURE AND content.json FIT TOGETHER
================================================================================

  When the site renders the Physics subject page, it does this:

    1. Reads  content.json
    2. Finds the subject with  slug: "physics"
    3. Lists every entry in its  "chapters"  array
    4. For each chapter with  status: "available", the card is clickable.
       For each chapter with  status: "coming-soon", the card is muted.
    5. When you click a chapter, the site reads that chapter's  "files"
       array and renders one download card per file.
    6. The Download button's URL is built as:
           /assets/<subject slug>/<filename>
       So the file at  site/public/assets/physics/10 - Light... .pptx
       becomes  https://revio.vercel.app/assets/physics/10%20-%20Light... .pptx

  That's the WHOLE contract. If a filename in content.json doesn't match
  a real file in public/assets/<subject>/, the Download button will 404.
  Nothing else can go wrong.

  Rules of thumb:
     - Subject folders under public/assets/  match subject slugs EXACTLY:
             physics/
             chemistry/
             mathematics/
             biology/
             social-science/
     - Slugs in content.json are kebab-case, lower-case, URL-safe.
     - IDs (like "ph-ch10-light") are internal. Change them freely; they
       never appear in URLs.

9.  COMMON MISTAKES AND HOW TO FIX THEM
================================================================================

  a)  Download button gives a 404 / "not found"
      → Filename mismatch. The filename in content.json must match the
        real file on disk EXACTLY, character-for-character, including
        spaces, dashes, and case. Also check the file is in the right
        subject folder.

  b)  Chapter still shows "Coming Soon" after pushing
      → You forgot to change  "status": "coming-soon"  to  "available".
      → Or the JSON has a syntax error (missing comma, extra comma). Open
        content.json in VS Code, look for red underlines.
      → Or you pushed only the files but not the JSON. Re-run  git status
        to see what's pending.

  c)  Vercel build fails
      → Open the failed deploy in Vercel dashboard, expand the "Building"
        step. 90% of the time it's a JSON parse error in content.json.
        Fix it locally with  npm run dev  (it'll refuse to load), commit,
        push again.

  d)  Site works on Vercel but breaks on GitHub Pages after refresh
      → You forgot to set  base: '/revio/'  in vite.config.js. That's
        required for GitHub Pages subpath hosting.

  e)  My git push is rejected
      → Someone (probably you on another device, or the GitHub Actions
        workflow) pushed a commit you don't have. Run:
              git pull --rebase
              git push
        and you're fine.

  f)  File is too big to push (over 100 MB)
      → GitHub has a 100 MB per-file hard limit. Compress the .pptx
        (remove embedded videos or downsize images) OR host that specific
        big file on Google Drive and put the Drive share link inside
        content.json's "filename" field instead of a local filename. The
        Download button will happily open external URLs too — you'll
        just lose the "download this instantly" feel for that one file.

  g)  My .docx / .pptx opens in the browser instead of downloading
      → Modern browsers respect the "download" attribute on the button
        (already set), so it should always be a download. If a student
        reports otherwise, they're using an in-app browser (WhatsApp,
        Instagram) which override this — ask them to open the site in
        Chrome/Safari directly.

10. ADVANCED — IF YOU EVER WANT A DATABASE
================================================================================

Skip this section unless one of the "when you would outgrow this" bullets
in section 0 becomes true. The current setup can hold hundreds of chapters
comfortably.

If you DO decide to move to a database-backed model — say, for student
logins, personalised progress, or admin-panel uploads — the two easiest
options are Supabase and Firebase. Both have free tiers big enough for
the first year.

  OPTION 1 — SUPABASE  (recommended, closer to real backend)
  -----------------------------------------------------------
  Supabase gives you a Postgres database + object storage (for the actual
  pptx/docx files) + auth, all with a free tier.

  Migration outline:

    a) Sign up at  https://supabase.com  and create a project.

    b) Create the database schema:
           Subjects (id, name, slug, icon, description)
           Chapters (id, subject_id, number, name, slug, status)
           Files    (id, chapter_id, type, format, filename, size, storage_key)

    c) Upload each existing .pptx/.docx to Supabase Storage under a bucket
       called "assets". The public URL Supabase gives you for each file
       goes into the "storage_key" (or a full "public_url") column.

    d) Change the Revio frontend so that instead of importing
       content.json, it fetches from Supabase on page load:

           import { createClient } from '@supabase/supabase-js'
           const supabase = createClient(URL, ANON_KEY)
           const { data: subjects } = await supabase
             .from('subjects')
             .select('*, chapters(*, files(*))')

       Wire that into  src/utils/content.js.

    e) (Optional) Build an admin page that requires login (Supabase Auth)
       and lets you upload files + create chapter rows via a form. Then
       you never touch JSON again.

  Cost: $0/mo until you exceed 500 MB database / 1 GB storage. That's
  hundreds of chapters worth of docx/pptx.

  OPTION 2 — FIREBASE  (easier, less SQL, Google-hosted)
  -------------------------------------------------------
  Firebase Firestore = NoSQL document database. Firebase Storage = files.
  Same migration idea, different flavour.

    a) Create a Firebase project at  https://console.firebase.google.com
    b) Enable Firestore (in "test mode" for now — tighten rules later).
    c) Enable Cloud Storage. Upload files, get public URLs.
    d) Add the firebase npm package:
             npm install firebase
       and read from Firestore in the same place content.json is currently
       read.

  For your use case (Class 10 CBSE, a few dozen chapters, no user logins),
  either database is OVERKILL. Really. Recruiters will not mark you down
  for using JSON — in fact, static-first architecture is currently a
  well-regarded pattern (see: Next.js SSG, Astro, Hugo).
